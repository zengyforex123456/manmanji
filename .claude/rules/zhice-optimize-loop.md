# 智策分析 03 — 数据驱动持续改善

## Trigger
"改善功能" "优化转化" "数据驱动" "A/B测试" "迭代"

## Input
- `docs/analysis/user_insight_*.md` — 最近用户分析报告
- `data/metrics.json` — 最新行为数据
- `data/feedback.json` — 用户反馈
- 产品功能列表（来自PRD）

---

## Action

### Step 1: 功能改善优先级排序

基于用户数据，用 **ICE 评分模型** 排序改进项：

```
ICE = Impact(影响范围) × Confidence(置信度) × Ease(实现难度)
每项1-10分，乘积排序
```

| 改进项 | 数据依据 | I | C | E | ICE | 优先级 |
|--------|---------|:--:|:--:|:--:|:--:|:-----:|
| 新手模式减为5题 | 开始→完成率<30% | 8 | 9 | 10 | 720 | P0 |
| 错题完成后弹窗引导 | 错题重做率<20% | 7 | 8 | 9 | 504 | P1 |
| 增加夜间模式 | feedback含需求 | 6 | 10 | 6 | 360 | P1 |
| 首页增加"换科目"入口 | 多科目用户<10% | 5 | 6 | 8 | 240 | P2 |
| ... | ... | | | | | |

### Step 2: A/B测试方案生成

针对ICE最高分项，自动生成测试方案：

```markdown
## A/B测试: 新手模式题数优化

**假设**: 新手模式从10题减为5题，开始→完成率提升≥20%

**对照组 A**: 当前（新手模式10题）
**实验组 B**: 新手模式5题

**关键指标**:
- 主指标: 开始→完成率
- 辅助指标: 次日留存率、NPS

**分流**: 50/50，按user_id哈希
**样本量**: 每组≥100次模式启动
**测试周期**: 7天
**显著性**: p<0.05

**决策规则**:
- B组完成率显著提升 → 全量上线
- 无显著差异 → 保留A组，尝试其他变量
- B组完成率显著下降 → 立即停止
```

### Step 3: 内容效果评估

分析现有内容的转化数据（如果有埋点）：

```
内容标题 → 曝光 → 点击 → 注册 → 付费
                ↓        ↓       ↓
             CTR%    CVR%    付费率%

找出:
- 最高CTR的标题模式（如"数字+结果"型 vs "问题"型）
- 最高CVR的内容类型（经验分享 vs 攻略 vs 对比测评）
- 最低CPA的内容渠道组合
```

### Step 4: 改善→验证→再改善闭环

```
每次改善后强制运行:
  T+1天: 检查关键指标变化方向
  T+3天: 判断是否需要调整
  T+7天: 写改善效果验证报告
  T+14天: 决定固化/继续优化/放弃

验证通过 → 写入 docs/analysis/improvement_log.md
验证失败 → 分析原因 → 调整方案 → 重新测试
```

### Step 5: 营销内容优化

基于用户答题数据，提取**可用于营销的真实数据**：

```
从 metrics.json 提取:
- "用户平均每天刷XX题" → 用于证明"碎片时间也能备考"
- "正确率从XX%提升到XX%" → 用于证明"刷题真的有效"
- "最高频错题TOP3" → 用于制作引流内容"这3题90%的人都错了"
- "用户最活跃时段XX点" → 指导推送时间
```
