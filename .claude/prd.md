## 四、离线优先架构（核心体验）

### 4.1 设计原则

```
                  ┌─────────────┐
                  │  用户操作    │
                  └──────┬──────┘
                         │
                         ▼
              ┌─────────────────────┐
              │  先写入 IndexedDB    │  ← 每答一题立即持久化（50ms内）
              │  （主存储，异步）     │
              └──────────┬──────────┘
                         │
                    ┌────▼────┐
                    │ 再更新 UI │  ← 不等待网络
                    └────┬────┘
                         │
              ┌──────────▼──────────┐
              │ 后台同步到          │
              │ localStorage（热备份）│
              └─────────────────────┘
```

**核心承诺：用户点击选项 → 50ms内数据落盘。浏览器崩溃/断电 → 进度不丢失。**

### 4.2 断电/崩溃恢复流程

```
用户正在刷题 → 突然断电/浏览器崩溃
                    │
                    ▼
        用户重新打开浏览器
                    │
                    ▼
         读取 IndexedDB progress 表
                    │
                    ▼
        找到最近一条 lastReview 记录
                    │
                    ▼
        恢复到断电前科目 + 模式 + 最后答题位置
                    │
                    ▼
        显示："检测到上次学习中断，已恢复到第X题"
```

### 4.3 离线状态矩阵

| 场景 | 网络 | 行为 |
|------|------|------|
| 首次访问 | 有网 | fetch JSON → IndexedDB 缓存 |
| 首次访问 | 无网 | 提示"需要网络连接加载题库"，显示已缓存科目 |
| 再次访问 | 有网 | IndexedDB 秒开 + 后台静默更新题库版本 |
| 再次访问 | 无网 | IndexedDB 秒开，顶部显示灰色离线指示器"📡 离线模式" |
| 刷题中 | 断网 | 无感知继续刷，进度正常保存到 IndexedDB |
| 刷题中 | 恢复网络 | 无感知，后台同步 |
| 弱网(2G/3G) | 高延迟 | 加载超时5s→提示"网络较慢，已切换离线模式"，使用缓存 |

### 4.4 Service Worker 缓存策略

| 资源类型 | 策略 | 说明 |
|---------|------|------|
| HTML | Network First | 确保拿到最新版本 |
| CSS/JS（Vite构建产物） | Cache First（带hash版本号） | 内容不变、永久缓存 |
| 题库JSON | Stale-While-Revalidate | 先返回缓存→后台更新→下次访问用新版 |
| Google Fonts | Cache First | 字体文件不变 |

## 五、UI 设计规范（学习效果优先+极简化）

### 5.1 设计原则

| 原则 | 说明 |
|------|------|
| **单焦点** | 每屏只做一件事。刷题时只有题目，零干扰 |
| **两步到达** | 任何功能从首页≤2次点击可达 |
| **信息最小化** | 首页只显示2个关键数字，其余收起 |
| **行动优先** | 最大按钮="开始刷题"，视觉权重=使用频率 |
| **渐进呈现** | 默认展示最常用路径，高级功能折叠在"更多" |

## 六、AI引擎技术路线（P2）

```
AI引擎架构（Phase 4 平台化）：
  答题数据 → 错因诊断 → "你在需求弹性计算上反复出错，建议复习第2章第3节"
  知识图谱 → 弱项识别 → 雷达图盲区标注 + 专项练习计划
  SM-2状态 → 自适应出题 → LLM约束生成个性化题目
  用户提问 → RAG(教材) → LLM回答(带出处)
```

| 指标 | 传统方案 | AI引擎方案 |
|------|---------|-----------|
| 错因分析 | 仅统计对错 | 识别概念混淆/计算失误/记忆遗忘 |
| 题目补充 | 人工5-15元/题 | LLM生成0.1-0.5元/题+人工抽检 |
| 答疑响应 | 无/人工客服 | RAG+LLM秒级+出处可追溯 |

## 七、技术栈

| 层 | MVP | 平台化 |
|----|-----|--------|
| 构建 | Vite + Vanilla JS | Next.js + Taro |
| 存储 | IndexedDB(Dexie) + localStorage热备份 | MongoDB + Redis |
| 题库 | JSON分文件(public/data/) | CDN + MongoDB + ES |
| 离线 | Service Worker + IndexedDB | 同左 + Background Sync |
| AI | LLM API离线出题脚本 | DeepSeek LoRA在线推理 |

## 八、架构决策

1. **离线优先** — 所有写入先落 IndexedDB，网络恢复后异步同步
2. **答即存** — 每道题选择答案后 50ms 内完成持久化，不做批量保存
3. **纯前端MVP，预留API签名** — 先验证方向，渐进接入后端
4. **配置驱动科目** — 新增科目=JSON+题库，零代码
5. **渐进模块化** — 数据→算法→UI，每步保持可用
6. **废弃dist/，Vite重建** — 标准ES模块
7. **被动复习+免打扰** — Dashboard面板展示，不弹窗

## 九、错误处理与降级矩阵

| 故障 | 检测 | 降级 | 提示 |
|------|------|------|------|
| IndexedDB不可用 | try-catch | 内存+localStorage恢复 | "隐私模式，数据仅本次保留" |
| 题库JSON加载失败 | fetch catch | 重试+缓存兜底 | "加载失败，点击重试" |
| 断网 | navigator.onLine | IndexedDB缓存 → 完整刷题 | 顶部"📡 离线模式"灰色条 |
| 断电/崩溃 | 启动时读IndexedDB | 恢复到最后答题位置 | "已恢复到中断位置" |
| SM-2异常 | try-catch | interval=1天 | 无感 |
| localStorage满 | setItem catch | 清理最旧5条progress | "空间不足，已清理旧记录" |

## 十五、稳定性和安全需求

### 15.1 运行时稳定性

| 需求 | 措施 | 目标 |
|------|------|------|
| 内存泄漏防护 | 单页应用：组件销毁时清理定时器/事件监听/Canvas上下文 | 连续使用1小时内存增幅<20MB |
| 长时间运行 | 定时器最大间隔≤30s；SM-2计算限频≤1次/s | 连续刷题100题无卡顿 |
| 异常隔离 | 每个service try-catch包裹；单个模块崩溃不影响整体 | 题库加载失败→仍可查看已缓存内容 |
| 并发控制 | 用户快速连点选项→防抖300ms→只处理第一次点击 | 无重复提交 |
| IndexedDB事务 | 写入失败自动重试3次→仍失败→降级localStorage+提示 | 数据不丢 |

### 15.2 安全性

| 需求 | 措施 |
|------|------|
| XSS防护 | 所有用户输入(搜索框)textContent而非innerHTML；题库JSON来自可信源 |
| 数据完整性 | IndexedDB写入后立即读取校验；localStorage读写try-catch包裹 |
| 敏感信息 | 无密码存储；会员token仅内存保存不持久化；localStorage不存敏感字段 |
| 内容安全 | 题库JSON签名校验（可选）；第三方依赖npm audit 0高危 |
| 隐私合规 | 无用户追踪；埋点数据匿名化；不采集设备指纹 |
